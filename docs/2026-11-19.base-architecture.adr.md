# 구조적 의사결정 기록(ADR)

## 1. 배경 및 문제(Context & Problem)

> 어떤 문제를, 왜 해결해야 하는지

- 인프라 구성을 관리하는 Terraform 프로젝트를 운영 중이었다.
- 선언형 도구 특성 상, 동적으로 구조를 관리하기가 어려웠다.
- 프로그래밍 방식을 지원하는 Pulumi 기반으로 전환하기로 했다.
- 두 도구의 구조적 차이 때문에, 모듈 구성 방식을 바꿔야 한다.

## 2. 결정 사항(Decision)

> 어떤 결정을, 왜 내렸는지

- 의도치 않은 리소스 변경을 막기 위해 Terraform 동작 CI 구성부터 제거한다.
- 자동화 가능성부터 빠르게 파악하기 위해 Pulumi 동작 CI 구성을 준비한다.
- 의도치 않은 리소스 변경을 막기 위해 Pulumi 동작은 미리보기로 제한한다.
- 코드 구성보다 재현 가능성부터 파악하기 위해 상태부터 마이그레이션한다.
- 이력이 혼란스러워지는 것을 막기 위해 가장 기반이 되는 요소부터 반영한다.
- 기존 모듈 분리 기준은 개념적으로 잘 정리되어 있으니, 가능하면 유지한다.
- data, local, variable 모듈은 관리 편의성을 위해 config 모듈로 통합한다.
- 관리 편의성을 위해 불필요한 provider 모듈은 없애고, index 모듈을 추가한다.
- import 구문의 가독성을 위해 경로 구조를 단순화하고 경로 별칭을 사용한다.
- 중간 결과를 검증하며 진행하기 위해, 위상정렬 순서에 맞춰 리소스를 옮긴다.
- 의존성 계층은 줄바꿈으로 구분하고, 각 계층의 변수명은 오름차순으로 선언한다.
- 혼란을 막기 위해 Pulumi 코드로 옮긴 리소스는 Terraform 코드에서 제거한다.
- 모든 리소스를 옮긴 후, 최종 동기화를 위해 Pulumi 동작을 다시 활성화한다.

## 3. 검토된 대안(Considered Options)

> 어떤 선택을, 왜 하지 않았는지

- 파일 이름 순으로 리소스 이동: 계획은 단순해지지만, 중간 결과를 검증하기 어렵다.
- index, config 모듈 통합: 다른 모듈에서 설정을 참조하는 순간 순환 참조가 발생한다.
- 변수 대신 함수로 선언해서 의존성 계층 구분: 변수 선언은 피할 수 없어서 구조적으로 달라지는 게 없다.
- 언더스코어 접두사로 의존성 계층 구분: 쉬운 해결책이지만 계층이 늘어나면 변수명을 다 바꿔야 한다.
